The first nine cases create a fresh native Player and temporarily select generated native Charas synchronously. Its only borrowed Player field is the active zone context; recipes, flags, stats, domains, knowledge and other reference fields are independently initialized, with a runtime alias guard against the original Player. Fixture Player uses native default state, not the save's learned recipes/day count/karma. This keeps those side effects on the fixture without deserializing the original Zone/Region graph. Only game.player is swapped; no original Player/PC field is assigned. No frames or nested IEnumerator run while the fixture Player is active. Conditions, piety, dream/recipe state and karma act on the fixture Player/actor. Normal inventory is only read for before/after assertions. Every allocation/mutation is after RegisterRollback. Cleanup keeps the fixture Player selected during removal callbacks, marks only owned Charas as summoned to satisfy native Card.Destroy's faction guard, removes only tracked fixture Things/Charas, restores the original Player in finally, removes only the unique test Harmony owner, restores Unity RNG, and asserts the exact original Player/PC references and serialized state plus inventory quantities, ownership, root, position, slots and metadata. Cleanup failure is a failed result: stop the run and restore the disposable baseline. Shared world counters, messages, FX and other-mod callbacks are not claimed to be fully rolled back; baseline reload is mandatory.

Observer patches do not skip or replace native processing and do not change arguments/results. They count actual native calls and track generated/split UIDs. Actor changes and exception injection are separately tagged `fault_injection`. Missing source/faith/category, unsuitable split batch or unfulfilled native preconditions fail; they are not passing existence checks. Postboot source registration is explicitly `postboot_contract` coverage; it does not prove the boot prefix timing.

## Shared native state and ownership protection

Before native fixture allocation, Pr8NativeStateScope captures every static Stats-typed field, its object/raw-array/rawIndex binding, original raw values, and BaseStats.CC. Cleanup restores all bindings and CC after native callbacks, including creation/cleanup exceptions, then asserts references/indexes/data. Player/PC JSON checks are retained because those checks cannot detect shared bindings. Mutable original raw data is never repaired to manufacture a pass.

EClass.rnd uses Rand._random, independently of UnityEngine.Random. Before native allocation, the fixture swaps Rand._random for its own System.Random and isolates Rand.bytes. Native Rand.SetSeed/OnSleep may replace the fixture reference freely. Finally restores the original unconsumed Random reference, baseSeed, MaxBytes and original bytes reference. Reflection captures original Random fields without drawing a sample and detects consumption even if the old reference is restored. Unity RNG restoration remains separate. All eleven cases use this native scope, and the original Random stream must remain untouched.

Pr8CardOwnership captures pre-generation map/PC/global/manager card trees and CardManager.uidNext. Every original UID is excluded, including uncaptured older UIDs via the native UID floor. Native Card.Create prefix observes only fresh zero-UID allocations before creation callbacks; a split must originate from an owned source and receive a new non-original UID. Returning an old/unobserved item from a generator never grants ownership. Box clearing checks the full recursive ownership tree before deleting anything. Native Card.Destroy prefix repeats that check on every recursive invocation, so callback insertion after an outer check fails before deleting the inserted item. Held cards are also part of the guarded actor tree. Unknown/foreign content is preserved, cleanup fails, and the operator restores the disposable baseline; the fixture does not remove, repair or retag that content. Prepare/verify reload cleanup uses this same guard; persisted nodes require exact manifest/source/name/owner validation before individual authorization.

Offline tests exercise actual native Stats.Set/Rand methods for all bindings, seed replacement and setup/cleanup faults; unrestored raw/index/CC/static object, RNG reference/settings, prior RNG consumption and original raw-data mutation must fail. Generic ownership tests use the same runtime ledger with inserted original UIDs, unobserved old/new UIDs, UID collision, nested foreign content, substituted split result, insertion after the outer precheck, and an unauthorized persisted child. They do not execute native Card.Create/Destroy or game callbacks.
