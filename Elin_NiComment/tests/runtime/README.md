# PR7 NiComment native lifecycle integration cases

These cases run through native `Chara.Die` and `Quest.Complete`, with the already-loaded NiComment prefix/postfix/finalizer. They never call the production gate directly, install a second product patch, create a stub overlay, or replace `FireBarrage`/`NiCommentAPI.Send`. All observations use one unique `runtime.pr7.ni.<token>` Harmony owner and exact signatures; rollback calls `UnpatchSelf` and asserts that owner is absent.

## Operator prerequisites

Use the existing `runtime-test-v2` smoke builder/runner and select one CaseId at a time. The case independently requires PC.Name containing `RUNTIME_TEST`, a live unmounted idle PC of level 1..50, noncriminal karma, enabled NiComment and its real initialized overlay. Never use an ordinary save. Back up the dedicated test save and reload it after every case, including successful cases, before running the next. Do not save generated fixtures; automatic/manual saves during the synchronous test must be disabled by the runtime operator. A cleanup failure blocks further PR7 cases in that submission and requires abandoning the run and reloading the dedicated save.

Disable LLM reactions before boot/loading the test save. Prepare requires `EnableLlm=false`, an absent or inactive provider, and no in-flight request. The cases do not alter config entries, provider state, credentials, external-send hooks, other automation, or ConfigFile.SaveOnConfigSet. If the guard rejects, the runtime operator must prepare/restart the isolated session; do not force a provider or overlay stub to pass.

The normal game's PC is never passed to `Die`. Death targets are direct results of `CharaGen.Create("bat", generationLevel)`, tagged with a unique test name, explicitly initialized with native `SetLv(requestedLevel)`, then placed with native `Zone.AddCard`. Create's second argument is `genLv`, not a contract that the returned NPC has that exact `LV`: Card.Create uses source DefaultLV/blueprint, and Chara.OnCreate computes its level from those values. The repository's SourceChara.xlsx bat row has LV2, so assuming Create("bat",1) returns LV1 was incorrect. No source row/shared blueprint is changed; a pending blueprint is rejected rather than consumed. Only the already-owned generated NPC is scaled. Native SetLv fills its HP/mana and calculates stamina; the test asserts these results without forcing alive/dead/zone/map flags or filling HP manually. PC is only the origin for eligible kills. `DeathSentence` takes the native final-death route without normal blood/random SpawnLoot; the faint control calls the ordinary native Die branch with host links between two generated NPCs. It proves the native mounted/faint branch, not the player-facing riding command.

The old LV2 minimum existed solely for the lower-LV kill control. At PC LV1, that control now generates/scales a normal LV1 NPC, registers rollback, then sets only that generated NPC's native `LV` property to 0. It keeps the actual `NPC.LV < PC.LV` precondition and real Die/finalized/zero-notification assertions. This is synthetic numeric boundary setup, not natural LV0 spawning. Other controls stay at ordinary explicitly initialized levels. The boundary property's native setter writes only `_ints[25]`; SetLv is used for positive native initialization, never for the synthetic LV0 adjustment or its rollback. The NPC's original LV is restored and asserted before fixture destruction, including exception cleanup. PC LV and experience are captured and asserted unchanged after rows and at final baseline comparison; the test never writes either value.

Before generation, the death fixture checks activeZone/map identity, active PC, ConFaint source and native AttackSource special-death values. Before placement it checks a detached living initialized NPC, positive exact level/HP, and an in-bounds point without a full block (Map.OnCardAddedToZone can otherwise destroy that block). Placement is verified by native currentZone, parent, exactly one map reference, bounds and the original active/LV/alive assertion. Before all 11 death rows, live fixtures must retain these contracts, exact UID/reference ownership, no summon/global/faction/boss/death-scream state, and positive HP; mounted links must be between owned living NPCs. The already-dead row requires its native detached dead instance, not a newly fabricated object. Reentry/exception/skip expectations and actual native body/event assertions are unchanged.

`fixture_created`, `fixture` and `death_before` logs expose requested/native/source/gen level, HP/dead, active/current-zone/parent/map/bounds and host state before operations/failures. The previous combined setup assertion did not log its operands, so the original failure does not independently prove which operand failed at runtime. The genLv/exact-LV contract error is confirmed from native code and source metadata; the next run must retain the detailed diagnostics if another precondition fails.

## Restoration and ownership

Rollback is registered before fixture additions/patching and runs in reverse order: remove/verify observer owner, remove only generated quests/NPCs/items, restore original karma and Unity random state, assert baseline, then restore/assert native shared RNG and Stats bindings. The final shared-state action is registered before baseline construction so it still runs when setup, fixture cleanup or baseline assertions throw; the unchanged shared runner continues all rollback actions after a failure. The snapshot records original world/PC identities, map/dead/global/carryover membership, every existing Chara's HP/dead/destroyed/LV/host/ride/conditions/inventory, existing quests/task state and membership, quest completion sets, current zone completion set, PC party and existing item quantity/parent/descendants. Unknown changes fail the invariant and require save reload; they are not overwritten to manufacture a pass.

Native `Rand.SetSeed` replaces `Rand._random`; Unity random restoration cannot restore this generator. Generation also calls `EClass.rnd`/`Rand.rnd`/`System.Random.Next` before a later SetSeed, so the original Random may already have advanced. The test captures its exact reference, baseSeed, both internal cursor values and a clone of its 56-int seed array, then restores cursor values, original array identity/contents and original Random reference without drawing random values to assert restoration. Unsupported Random subclasses/layouts are rejected before fixture mutation. All nine native Stats singleton bindings (`raw` array reference and `rawIndex`) and independent `BaseStats.CC` are captured directly without calling rebinding Chara.mana/stamina getters. Cleanup restores those pointers/indexes, including null values, and asserts exact identity; it never rewrites an existing Chara's stat-array contents. This fixes shared scratch-state restoration; it does not demonstrate any user-save corruption.

At NPC generation, all descendant item references and UIDs are captured. Immediately before recursive native Destroy, every child must still be an exact captured reference/UID; every captured item must have an exclusively owned root (its generated NPC, known generated containers, original zone, or detached). Unknown children, changed UID/reference, external ownership, held objects, global/faction ownership or a replaced world cause cleanup failure without Destroy of that contaminated fixture. Newly discovered items are never adopted as owned. Initial descendants that were dropped remain exact owned instances and are removed after the NPC. Existing actors/items/conditions are never explicitly removed or killed by the test.

Synchronous rollback is not a complete game-save restore: UID allocation, other RNG sources beyond the captured Rand/Unity generators, native UI/message/audio state and arbitrary other-Mod callbacks are not fully reversible. **Reload the dedicated save after every case.** No save/load, game launch, deployment, Steam copy or shared-runtime edit is performed by this implementation.

## Offline verification

`compile-offline.ps1` generates the csx using the unmodified shared builder, compiles a library wrapper against existing net472/game/Harmony references and the specified NiComment DLL, then emits the **unmodified csx** as a Roslyn script submission without evaluating it. It also executes seven ownership graph checks using native Card/Thing/Chara types allocated without constructors or Unity: known descendants, unknown grandchild, same UID/different reference, same reference/changed UID, external actor, unknown container, cyclic owner chain. Eleven additional checks use actual native Rand/Stats methods and the unchanged RuntimeTestContext rollback runner: side-effect-free capture, reference-only RNG insufficiency, exact next-64-draw sequence after restore, seed-array content/identity counterexamples, native SetSeed replacement/baseSeed, native mana getter contamination, all nine bindings/null arrays/independent CC, exceptions before/after SetSeed (including null CC), and final shared rollback despite earlier cleanup failure. These checks validate cleanup guards/shared-state restoration only, not gameplay. Output/TEMP should be isolated outside the repo and Steam. Existing 15 NiComment unit tests remain separate.

```powershell
& .\compile-offline.ps1 -RepoRoot <isolated-worktree> -OutputRoot <isolated-output> -NiCommentDll <built-Elin_NiComment.dll>
```
